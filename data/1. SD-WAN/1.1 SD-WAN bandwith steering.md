In this exercise, you'll explore one of the key new SD-WAN capabilities introduced in **FortiOS 8.0**: **Underlay Bandwidth Steering**.
<br>
Unlike traditional SD-WAN steering, which relies on latency, jitter, or packet loss, FortiOS 8.0 can now make routing decisions based on the <strong>available bandwidth</strong> of the WAN links.

<br>

<div class="defender-container">
<div class="defender-label">INFO</div>

<strong>Scenario</strong>

Your FortiGate has two WAN connections, both connected to an SD-WAN zone.

Initially, both WAN links provide the same available bandwidth, so new sessions can be distributed across either interface.

Using the <strong>WAN Simulator</strong>, you will artificially consume bandwidth on one of the WAN links and observe how FortiGate automatically adapts its path selection.

</div>

<br>

---

# Step 1 – Verify the Current State

Before making any changes, verify the available bandwidth of both WAN interfaces.

Run:

```bash
diagnose sys sdwan service4
```

Confirm that both WAN interfaces report approximately the same available bandwidth.
![WAN_sim_off.jpg](/files/ca8baf5e0d8877b09afc9d082ce5fe52/WAN_sim_off.jpg)

<br>

---

# Step 2 – Simulate ISP Congestion

Open the **WAN Simulator**.

Generate background traffic on the simulated WAN link by reducing its available bandwidth.

For this lab:

* Configure the WAN Simulator to consume approximately **90 Mbps** of bandwidth on **eth192**.
* Do **not** introduce latency or packet loss—only bandwidth consumption.

<br>

<div class="info">

The WAN Simulator emulates a congested ISP link without causing the interface to fail. This allows FortiGate to evaluate routing decisions based solely on the remaining available bandwidth.

</div>

<br>

---

# Step 3 – Observe the Current SD-WAN State

Run the following command again:

```bash
diagnose sys sdwan service4
```

Notice that the available bandwidth may not have changed yet.

This is expected.

FortiGate evaluates available bandwidth when **new sessions are created**.

<br>

---

# Step 4 – Trigger a New Session

From the Windows workstation, generate new Internet traffic.

Examples include:

* Browse to a website
* Start a download
* Refresh an existing webpage

Once a new session has been created, run:

```bash
diagnose sys sdwan service4
```

Notice that we now see port8 as preferred and a drop in bandwith on port9.
![WAN_sim_on.jpg](/files/bc02f7820a78f51cb3a95c0554d31f20/WAN_sim_on.jpg)

<br>

---

# Expected Result

After the new session is created:

* The WAN interface connected to the simulator should report **significantly less available bandwidth**.
* The unaffected WAN interface should remain unchanged.
* New sessions should now be steered toward the interface with the most available bandwidth.

This demonstrates how **Underlay Bandwidth Steering** dynamically selects the best path without requiring packet loss, latency, or an interface failure.
