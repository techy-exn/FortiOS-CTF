In this exercise, you'll explore one of the key new Administrator access hardening capabilities introduced in **FortiOS 8.0**: Disallowed login methods.
<br>
The disallowed-login-methods configuration setting allows administrators to explicitly block specific access methods for logging into the FortiGate, such as console, GUI, SSH, or Telnet. Specifying the GUI access method will prohibit the ability of the administrator to log into the FortiGate through HTTP and HTTPS.
</p>

<br>

<div class="defender-container">
<div class="defender-label">SCENARIO</div>

A company has a FortiGate administrator who only manages the firewall through the HTTPS GUI. To reduce the attack surface, the company blocks SSH and Telnet access specifically for that admin account.

Admin → HTTPS GUI → ✅ Allowed
<br>
Admin → SSH       → ❌ Blocked
<br>
Admin → Telnet    → ❌ Blocked

**Benefit**: Even if SSH is enabled on the FortiGate for other purposes, that administrator's credentials cannot be used to log in via SSH.

</div>

<br>

## Step 1 – Check the current config
Login into the **FortiGate 1** and open up the **CLI Console** then check the current config on admin user:

```
config system admin
```
```
show
```

You should see a default config with No **disallowed-login-methods** set.:

![show-config-admin.jpg](/files/2cb446f1edd56b59a32b01467cf6863a/show-config-admin.jpg)

---
## Step 2 – Enable administrator access hardening

Open the **CLI Console** and navigate to the admin user:

```
config system admin
```

Then

```
edit admin
```

Now if you enter ``set ?`` one of the first fields show **disallowed-login-methods**:

![disallowed.jpg](/files/a600d42ce8e930eb7199d7e728f56e23/disallowed.jpg)

Next let's configure the admin to take away access via **ssh** and test the config with **PuTTY** on the Windows Client.

```
set disallowed-login-methods ssh
```
```
next
```
```
end
```
