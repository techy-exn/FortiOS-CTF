<div class="defender-label">Did you know?</div>

**FortiGate High Availability** (HA) **prevents** the firewall from becoming a **single point of failure** and provides fast failover when hardware, links, routes, or other monitored components fail.

Fortinet provides three main HA approaches:

* FGCP — FortiGate clustering for redundancy/failover, with Active-Passive or Active-Active operation.
* FGSP — synchronizes sessions between FortiGates, typically when external load balancers/routers distribute traffic.
* VRRP — provides router redundancy and interoperability with third-party VRRP devices.

</div>

## Step-1: Configure FortiGate 1

It's now time to set up the HA cluster. In our scenario we will choose with an Active-Passive cluster. Login to `FortiGate 1` and go to `System  > HA`

![System - HA](/files/455183a895099999325415813f24455c/Blank_HA_Settings.jpg)

You will see that this is standalone by default. On the first FortiGate configure the following settings:

![FG1 - HA](/files/1b0e65d7d5f764c72b63105129ea141b/HA_Config_FG1.jpg)

<div class="info">
	
* Device Priority is not shared within the HA cluster 
* The Option increase priority effect is the same as enabling the override setting in CLI. This will change the primary unit selection order. This is to be configured per FortiGate
* You can't have multiple FortiGate clusters with the same group ID in the same layer 2 network. It will cause issues
* Proxy based sessions can't be synced
* You can work with backup heartbeat interfaces as well

</div>
